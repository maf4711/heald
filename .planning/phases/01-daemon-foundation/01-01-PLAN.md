**HealdService.swift** — Conforms to `Service` protocol from ServiceLifecycle. Phase 1 = idle skeleton. The shutdown log entry MUST be written inside `run()` before `gracefulShutdown()` returns — NOT in main() after `serviceGroup.run()` completes (OSLog flushes asynchronously and the process may exit before the flush). Use `withGracefulShutdownHandler` to guarantee the log is written synchronously on shutdown:

```swift
import ServiceLifecycle
import OSLog

struct HealdService: Service {
    func run() async throws {
        Logger.lifecycle.info("HealdService running — idle (phase 1 skeleton)")

        try await withGracefulShutdownHandler {
            // Suspend until graceful shutdown is triggered.
            // This is a true suspension — no busy loop, no Timer, no Task.sleep loop.
            // CPU usage while suspended: 0%. RAM: Swift runtime only (~5-10MB).
            try await Task.sleep(for: .seconds(Int.max))
        } onGracefulShutdown: {
            // This callback runs synchronously on the shutdown signal.
            // Write shutdown log here — guaranteed before process exits.
            Logger.lifecycle.info("HealdService shutting down cleanly")
        }
    }
}
```

**main.swift** — @main entry point. Use `ParsableCommand` from ArgumentParser for `--version` support. ServiceGroup must include both `.sigterm` (launchd shutdown) and `.sigint` (Ctrl+C during development) as graceful shutdown signals:

```swift
import ArgumentParser
import ServiceLifecycle
import OSLog

@main
struct HealdApp: AsyncParsableCommand {
    static let version = "0.1.0"

    static var configuration = CommandConfiguration(
        commandName: "heald",
        abstract: "Self-healing macOS system daemon",
        version: version
    )

    func run() async throws {
        Logger.lifecycle.info("heald \(Self.version) starting")

        let service = HealdService()
        let serviceGroup = ServiceGroup(
            services: [service],
            gracefulShutdownSignals: [.sigterm, .sigint],
            logger: .init(label: "com.heald.daemon")
        )

        try await serviceGroup.run()
        Logger.lifecycle.info("heald stopped cleanly")
    }
}
```

Create `heald/launchd/` directory and write the LaunchAgent plist template. This file is a template — install.sh will replace the USERNAME placeholder with the actual username at install time via `sed`.

**Critical requirements for this plist:**
- `ProgramArguments` must use an ABSOLUTE path containing `USERNAME` as placeholder — launchd requires absolute paths; relative paths silently fail after reboot
- `KeepAlive: true` — launchd restarts the daemon if it crashes (required for DAEM-01)
- `RunAtLoad: true` — daemon starts immediately when the LaunchAgent is bootstrapped (required for DAEM-01)
- `ThrottleInterval: 10` — prevents crash-loop CPU saturation (required for DAEM-03; without this a crash loop saturates a CPU core)
- `ProcessType: Background` — prevents daemon from competing with foreground work (required for DAEM-03)
- `LowPriorityIO: true` — I/O deprioritized relative to user-facing processes (required for DAEM-03)
- `Nice: 5` — CPU scheduling priority reduced (required for DAEM-03)
- Do NOT include a `Disabled` key — it is overridden by `/var/db/com.apple.xpc.launchd/disabled.plist` and can cause silent load failures after reboot
- StandardOutPath and StandardErrorPath go to /tmp — readable without tooling

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.heald.daemon</string>
    <key>ProgramArguments</key>
    <array>
        <string>/Users/USERNAME/Library/heald/heald</string>
    </array>
    <key>KeepAlive</key>
    <true/>
    <key>RunAtLoad</key>
    <true/>

</dict>
</plist>
```
